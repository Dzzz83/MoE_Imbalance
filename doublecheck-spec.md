# Doublecheck spec

## Goal
Produce an evidence-based diagnosis of what is wrong with the DACE implementation and why prototype routing collapsed to \"always Expert B\" (33.91% routed vs 39.84% uniform), with every claimed cause backed by a measured number obtained from the real trained DACE checkpoints. No fixes are implemented this round.

## Scope
IN SCOPE: read-only analysis using local artifacts only — checkpoints/DACE_{A,B,C}_best.pt, checkpoints/DACE_{B,C}_history.json, data/cifar-100-python, data/processed/lt_{train,val}_indices.npy; new read-only diagnostic script(s) under scripts/; a written findings report under docs/. May reuse the six original expert checkpoints (LAL/PaCo/Mixup/CE/BS) for comparison. OUT OF SCOPE: any edit to scripts/train_dace_{a,b,c}.py, scripts/evaluate_dace.py, losses/*, models/*, data/*; any retraining; any fix design or remediation code; any edit to docs/results.md, docs/research-findings.md, or docs/partitioned-specialization-plan.md.

## Acceptance criteria
The diagnosis is complete when all five questions are answered with numbers reproducible by a command committed in the repo, and each answer is explicitly labelled CONFIRMED (measured) or SUSPECTED (reasoned but unmeasured):\n(Q1) Why the contrastive routing loss never trained: quantify the KL(A||B) and KL(avg(A,B)||C) distributions on the long-tailed validation split (mean/median/percentiles), show the agree/disagree split produced by tau=0.1 versus candidate taus {0.3, 0.5, 1.0, 2.0}, and demonstrate that ~96-99% one-sided labels leave the contrastive objective without a discriminative signal. Cross-check against the recorded training curve (L_contrastive pinned at ln(127)=4.8442 for batch 128; agree_ratio 0.000->0.039 for B and 0.000->0.011 for C).\n(Q2) Whether the routing score predicts expert correctness: report AUROC of score_B vs B-correct and score_C vs C-correct on the validation split. AUROC near 0.50 falsifies the routing premise; AUROC materially above 0.50 means the signal exists and the inference logic is at fault.\n(Q3) Whether the DACE experts are too weak: report per-expert BA for A/B/C on the balanced 10K test set alongside the documented originals (PaCo 41.17, LAL 39.96, BS 39.99, Mixup 37.52, CE 36.64) and the uniforms (DACE 39.84 vs documented 45.68), stating plainly whether routing alone could close that gap.\n(Q4) Whether score comparability and the 0.7 fallback are fixable by tuning alone: report mean/std/min/max for score_a, score_b, score_c (are they on a comparable scale?), the argmax win distribution, and the measured firing rate of the cosine-similarity fallback at thresholds {0.3, 0.5, 0.7}.\n(Q5) Oracle headroom and all-wrong ceiling for these three experts: report the all-wrong fraction, the correct-count distribution (0/1/2/3 correct), and oracle BA on the validation split.

## Failure modes
Missing artifact (checkpoint, history JSON, or split .npy): report the exact missing path and stop; do NOT substitute random or assumed values.\nCPU runtime too slow for a full split: subsample deterministically with a fixed seed, state the subsample size and seed in the report, and never silently alter the evaluation protocol.\nEvidence ambiguous or a metric sits at chance: say so explicitly. Do not present a mechanism as confirmed when the measurement is inconclusive.\nCause not measurable locally (e.g. requires a GPU or the Kaggle environment): label it UNVERIFIED and provide the exact command to run on Kaggle rather than guessing (AGENTs.md section 3 \"No Guessing\" rule).\nData-leakage risk: the validation split may be used for measurement and post-hoc prototype statistics only; it must never be used to fit a model or select a routing policy reported as final. The 10K test set is for reported metrics only.\nA diagnostic that crashes on the CUDA device-mismatch path: run on CPU deliberately and note that the CUDA path is unexercised locally (this machine reports torch.cuda.is_available() == False).

## Priorities
Evidence over speed: every conclusion needs a number from an actual run, not reasoning alone.\nAlways distinguish CONFIRMED from SUSPECTED, and state the boundary of what was measured.\nPrefer measurements on the real DACE checkpoints over synthetic proxies; use synthetic models only to establish a baseline reference value (e.g. ln(batch_size) as the chance level).\nCompute is unconstrained within the session (~1.6h per full retrain measured; 971s + 2017s + 2697s on T4), so spend runtime to get a rigorous answer rather than a cheap approximation.\nOptional / droppable if time is tight: report polish, extra ablations beyond the five required questions, and any analysis not tied to Q1-Q5.\nWhen rigor and convenience conflict, choose rigor and record the extra cost.
